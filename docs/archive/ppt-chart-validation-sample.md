# 可编辑 PPT 图表校验示例

## 文档用途与生成目标

本材料用于验证“Markdown 文档 -> 来源小节 -> PPT 大纲 -> 页面正文 -> 原生图表或图示”的完整链路。汇报主题是“客户服务能力升级”，受众为管理层，语气保持专业、具体、可追溯。

本材料中的数字均为演示数据，正式汇报前应替换为真实业务来源。所有数据事实都使用完整句式表达，保留指标、分类、数值、单位、时间和统计范围，便于生成大纲时形成可验证的 `EvidenceItem`。

本材料刻意覆盖以下页面视觉类型：默认图表自动判断、折线图、饼图、条形图、柱状图、时间线和流程图。每个图表页面只使用一组同口径数据，避免把不同指标、不同单位或不同统计范围混在一张图里。

- 阶段：方案设计；时间：2026Q4；交付物：服务分层方案、指标口径和试点范围；范围：客户服务能力升级项目。
- 阶段：试点运行；时间：2027Q1；交付物：试点结果、风险清单和改进建议；范围：客户服务能力升级项目。
- 阶段：规模推广；时间：2027Q2；交付物：标准模板、培训材料和运营看板；范围：客户服务能力升级项目。

## 流程图：从业务素材到可编辑 PPT

本页是流程表达页，建议使用 `evidence_kind=flow`、`visual_type=flow`。流程节点使用“步骤 + 说明”表达输入、处理和输出，节点之间按先后顺序连接，不用卡片伪装箭头。

- 步骤：收集材料；说明：接收 Markdown、Word、PDF、TXT 或项目主题，保留来源标题和段落位置。
- 步骤：拆分小节；说明：Markdown 解析器按标题、段落和列表提取来源小节，形成稳定的来源引用。
- 步骤：规划大纲；说明：根据页数、受众、场景和来源内容生成页面目标、关键点与证据形态。
- 步骤：校验证据；说明：检查引用原句、指标、数值、单位、时间、范围和可比数据是否一致。
- 步骤：生成正文；说明：把页面大纲展开为标题、图表、图示、解读和来源说明。
- 步骤：导出校验；说明：检查布局、图表数据、来源绑定和 PPTX 回读结果，发现错误则阻断导出。

流程结论：只有在来源可追溯、证据口径一致、内容块和布局契约均满足时，页面才适合进入最终导出。

## 图表数据校验规则速查

以下规则用于检查本示例是否符合后端当前的内容契约：

- 趋势图只使用同一指标、同一单位、同一统计范围和至少两个不重复时间点；时间顺序按来源出现顺序保留。
- 构成图或分类比较图只使用同一指标、同一单位、同一统计范围和至少两个不重复分类。
- 每条证据的 `quote` 必须能在对应来源小节中找到；`metric`、`category`、`value`、`unit`、`period` 和 `scope` 不能与原句冲突。
- 图表类型只使用后端支持的 `line`、`pie`、`bar`、`column`；图示类型只使用 `timeline` 和 `flow`。
- 原生图表建议不超过 8 个分类和 3 条系列；本示例每个图表都只使用一条系列。
- 图表数据缺失、冲突或无法比较时，应回退为定性分析，不能为了生成图表补造数字。
- 流程图至少需要两个步骤；时间线至少需要两个阶段，并且每个节点应有清晰的标题和说明。
- 页面解读要区分事实、推断、建议和预测；不能把相关性直接写成因果，也不能凭图表外推来源没有提供的增长率。

## 汇报收束：决策与下一步

综合本材料，客户服务能力升级已经具备继续推进的证据基础：活跃客户数连续增长，服务资源结构已经明确，渠道和区域比较也暴露出可优化的差异。下一步建议确认试点范围、统一满意度与转化率口径，并在 2027Q1 试点结束后复盘是否进入规模推广。

需要管理层确认的事项：是否按现状盘点、方案设计、试点运行、规模推广四个阶段推进；是否优先复用智能助手和主动回访的服务机制；是否将区域团队差异纳入下一轮培训和运营改进。
