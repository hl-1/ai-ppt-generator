# 旅游规划 PPT 功能实现文档（预览）

文档日期：2026-10-08

当前状态：前端“旅游规划”分类入口已完成；相关 Key 已填写，天气接口已手动测试成功。地图、网页检索及其与旅行规划生成链路的连接尚待实现。

本文件保存对话中已预览的功能方案。“旅游规划”分类入口完成后的开发准备仅涉及代码阅读和接口文档查询，尚未修改本方案对应的功能代码。

## 一、实现目标

用户输入旅行需求后，项目查询天气、地图及可信来源，生成包含逐日行程、费用、住宿建议和预约事项的旅游规划 PPT。

**能查到的数据注明来源，缺失的数据明确标记，费用估算与实际报价分开显示。**

## 二、旅行条件

创建项目时补充以下信息，并允许从主题中自动提取后由用户确认：

| 条件 | 内容 |
| --- | --- |
| 地点 | 出发城市、目的地 |
| 时间 | 出发日期、返回日期、可接受的出发和返程时段 |
| 人员 | 成人、儿童、老人数量及年龄条件 |
| 预算 | 总预算或人均预算 |
| 偏好 | 交通方式、住宿区域、感兴趣的景点、游览强度 |

输入“春节去北京旅游规划”但未指定年份或日期时，先补充条件；日期不明的内容以建议草案呈现。

## 三、功能范围

| 功能 | 实现方式与输出 |
| --- | --- |
| 天气预报 | 和风天气查询对应日期的天气、温度、降水和风况；超出预报范围显示待更新 |
| 总路线与计划大纲 | 按地理位置、开放时间和旅行偏好组织景点，展示每天路线与行程摘要 |
| 出发与返程安排 | 根据用户日期、交通时长给出建议时段；实际车次、航班及票价需对应票务服务 |
| 景点门票 | 查询景区官网或官方售票入口，保留票种、适用人群、价格条件及来源 |
| 景点配图 | 使用经核对的实景图片，记录来源；Unsplash 为补充来源，匹配不到时允许上传 |
| 官方运营时间 | 查询开放、停止入园、闭馆及特殊日期公告，并检查是否适用于出行日期 |
| 路线成本 | 高德提供距离、交通方案和可取得的费用字段；其他交通费用明确标为估算 |
| 酒店或民宿 | 高德提供位置及周边信息，给出住宿区域与预订入口；实时房价、库存需住宿平台授权 |
| 季节适配 | 查询花期、雪季和活动信息；常年规律标为参考，不承诺某日一定开花或下雪 |
| 景点内部路线 | 优先依据官方导览图、推荐路线和入口信息，补充游览顺序与建议停留时间 |
| 打卡地点 | 结合官方介绍、可信资料及图片推荐具体位置，并标明开放或季节限制 |

## 四、生成链路

```text
完整主题与旅行条件
    -> 提取查询清单
    -> 查询天气、地图及官方资料
    -> 整理事实、来源和缺失信息
    -> 编排逐日行程并检查时间冲突
    -> 计算预算、生成预约待办
    -> 生成大纲供用户确认
    -> 使用同一份资料生成 PPT 正文与配图
```

天气使用已测试通过的 `days` 数据结构，按出行日期筛选。当前测试接口最多支持 10 天预报，远期旅行保留天气待更新状态。

官网检索使用 Firecrawl 搜索、抓取；网页内容作为外部资料处理。精确价格、时间和日期必须能对应原文，旧年份公告不能证明今年的安排。

## 五、规划与预算校验

- 每天检查景点开放日期、入园截止时间、交通耗时、用餐及休息时间，发现冲突后调整或提示。
- 所有费用区分“官方规则价格、供应商报价、估算、待查询”，注明人数、数量和适用条件。
- 后端按单价、数量和天数计算金额；缺价时展示已知小计及缺价项目。
- 预约规则和用户预约状态分别保存，生成规划不会将待预约事项标记为已完成。
- 雨雪、景区闭馆或预约失败时，提供可替换行程；无法验证的安排保留提示。

## 六、项目实现

复用现有 FastAPI、ARQ、数据库和 PPT 导出链路，增加旅行条件、查询任务、来源记录和结构化行程。

每次查询保存版本，大纲与正文使用同一版本；条件修改后旧结果标记失效。

查询阶段显示进度；设置单服务超时、有限重试及总时间限制。部分服务失败时保留已有结果和缺口。日志记录服务名、阶段、耗时、数量和错误码。

本地配置读取 `backend/.env`，线上使用部署环境配置或 `backend/.env.production`；增加天气、高德和检索的连通性检查。

相关服务的建议配置项：

```dotenv
QWEATHER_API_HOST=
QWEATHER_API_KEY=
AMAP_API_KEY=
FIRECRAWL_API_KEY=
UNSPLASH_ACCESS_KEY=
```

以上只列出配置名称，不包含实际密钥。天气、高德和网页检索的配置读取及调用逻辑仍需开发。

## 七、实施顺序

1. **数据接入**：配置检查、旅行条件、天气、高德地点和路线查询、官方资料检索及来源保存。
2. **规划生成**：逐日行程、时间校验、费用计算、住宿建议、预约待办及 PPT 内容生成。
3. **体验完善**：实景配图核对、内部游览路线、打卡推荐、替代方案和资料刷新。
4. **实时预订扩展**：取得供应商授权后接入酒店、车票及机票报价和库存。

## 八、验收标准

以“春节去北京旅游规划”为例，逐项覆盖上述功能。

- 每个确定的价格和时间都能追溯来源，任何缺失或估算都能在规划中识别。
- 出发和返程日期、人员、预算、偏好贯穿路线、住宿及费用计算。
- 超出天气预报范围时显示待更新，不用当前天气替代远期旅行天气。
- 旧年份活动或节庆公告不被标为当年已确认安排。
- 查询失败、超时及部分资料缺失有明确状态，任务不会无限停留在生成中。
- 修改旅行条件后旧资料被标记失效，大纲与正文不能混用不同版本的资料。
- 实景配图缺失时保留缺口，不将 AI 插图当成景点真实照片。
- 预约规则已核实与用户预约已完成分别保存。

第一版可生成有依据的规划草案，完整实时报价和库存取决于供应商接口权限。
